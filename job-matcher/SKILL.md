# 岗位雷达 · Job Radar

一个给 2027 届秋招生自己用的岗位筛选 skill。核心不是「搜得快」，是**判断得准**——把不值得投的挡在外面，把值得投的说清楚为什么。

## 执行前必读

动手之前，先读这两个文件，它们是判断依据：

- `references/01-候选人档案.md` —— 她是谁、会什么、边界在哪
- `references/02-输出规范与去重规则.md` —— 输出什么、怎么去重、硬规则

## 两种模式

### 模式 A · 搜索模式（主动找一批岗位）

触发：用户说「帮我找岗位」「跑一下招聘日报」等。

流程：

1. **搜索**。用 WebSearch，覆盖：实习僧、BOSS 直聘、牛客网、应届生求职网、目标公司官网招聘页。
   关键词方向（**故意覆盖「已知方向」+「新工种发现」两类**）：
   - `上海 AI 产品助理 2027届 校招`
   - `上海 小而美外企 数据分析 校招`
   - `上海 大模型应用 运营 2027届`
   - `上海 RPA Agent 交付 校招`
   - `上海 开发者社区运营 大模型 2027届 校招`        ← 新工种：AI 生态运营
   - `上海 开发者关系 AI 技能池 agent 生态 招聘`       ← 新工种：技能池 / 插件生态运营
   - `上海 AIGC 内容运营 校招 2027届`
   - 具体公司名 + `2027届 校招`

   > 看到档案里没列过、但明显长在 AI 产业链上的新岗位（社区 / 生态 / 标注 / 评测 / 交付等），**要主动收进来并标注「新发现工种」**，这正是这个 skill 比普通招聘聚合器有价值的地方。

2. **硬过滤**（不符合直接丢）：
   - 硬性要求硕士及以上
   - 不接受 2027 届
   - 非上海且非远程
   - 硬核技术岗（C++/Go 研发、深度学习框架研发、NLP/语音/多模态算法、算法竞赛）

3. **六维打分**。见 `references/02`。

4. **去重**。读取累积表全部历史，按「公司名+岗位名」规范化后比对。

5. **写入**。追加到累积表，更新「今日 Top3 推荐」。

6. **回报**。告诉用户：今天新增几条、跳过几条重复、Top3 是哪三个、有没有需要她立刻确认的（比如某岗位截止日期很近）。

### 模式 B · 评估模式（评估一个具体岗位）

触发：用户粘贴一段 JD。

流程：

1. 读取 `references/01-候选人档案.md`
2. 输出四部分：
   - **岗位卡片**（公司/岗位/城市/链接/截止/是否接受 2027 届本科/是否真 AI）
   - **六维打分表**（每维分数 + 一句理由 + 总分 + 结论）
   - **风险与建议**（最可能卡住她的硬门槛 / 简历哪段经历放最前 / 投递前要补什么）
   - **信息不足提示**（缺什么就说缺什么，不要猜）
3. 如果用户说「我要投这个」，接着用 `prompts/02-简历定制建议.md`

## 硬规则

1. **不编造岗位、不编造链接。** 来源不明的宁可不收。链接必须真实可访问。
2. **查不到就写「未披露 / 未标注 / 信息不足」，绝不猜。**
3. **匹配度是参考，不是判决。** AI 只能读 JD 文字，不知道内部筛选规则、不知道招几个人。这个边界要如实告诉用户。
4. **「是否真 AI」单独判断。** 很多岗位挂 AI 名字实际是传统运营，这一列能滤掉一半噪音。
5. **英语单独看。** 她目前只有四级、六级 2026 年 12 月考。卡六级的岗必须显式标出来。
6. **只追加不覆盖。** 历史数据永远不删。
7. **打分要狠。** 打人情分等于没打。该说「不建议」就直说。
