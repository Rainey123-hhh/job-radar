# 岗位雷达 · Job Radar

一个给 2027 届秋招生自己用的岗位筛选 skill。

> **起因：** 秋招要同时盯几十家公司，每天在公众号、牛客、BOSS、公司官网之间来回翻，还得一条条对照自己够不够格。效率低，而且容易漏掉真正合适的。
>
> **核心不是「搜得快」，是「判断得准」**——把不值得投的挡在外面，把值得投的说清楚为什么。

---

## 这是什么

一个 **skill**（`SKILL.md`），不是一个软件。

它是一份结构化的说明文件，AI 读完之后就知道该怎么帮你筛岗位：先看你是谁、再看这个岗要不要你、最后按固定格式输出。**没有一行代码，但它是真的能跑的**——之前基于同一套逻辑的自动化已经连续跑了两个多月（2026 年 7 月 – 9 月）。

顺带一提：我在壹沓科技实习时写过 AI skill，这是我自己写的第一个。

## 怎么用

### 方式一 · 直接当 skill 用

把这个仓库放到本地的 skills 目录（Claude Code / Codex / WorkBuddy 都支持），然后说：

- 「用 job-radar 帮我找今天的岗位」
- 「用 job-radar 评估一下这个 JD」

### 方式二 · 复制提示词

不想装也没关系，把 `SKILL.md` + `references/` 里的两个文件一起贴给任意 AI（Claude / 豆包 / DeepSeek 都行），效果一样。

### 方式三 · 配成每天自动跑

新建一条定时自动化，每天早上 9–10 点执行一次，指令引用 `SKILL.md`。跑完自动追加到累积表。

## 六维匹配度怎么打

| 维度 | 看什么 |
|---|---|
| 学历与院校门槛 | 是否卡 985/211、是否卡硕士 |
| 专业匹配度 | 经济统计 / 数理背景是否被接受 |
| 技能匹配度 | SQL、数据工具、AI 工具 |
| 实习经历相关度 | AI 相关实习是否被认可 |
| 英语要求 | **是否卡六级**（目前只有四级，这是真实短板） |
| 方向契合度 | 真的 AI，还是挂名 |

满分 30。24+ 优先投，18–23 正常投，12–17 有空再说，12 以下不投。

**「是否真 AI」是独立的一票否决项**——挂名的岗位无论多少分都降一档。

## 它的边界（重要）

**匹配度打分是参考，不是判决。**

它只能基于 JD 的文字判断，不知道：

- 这家公司内部的真实筛选规则
- 今年这个岗位实际招几个人、收到多少简历
- HR 会不会因为某个非公开条件直接筛掉

所以低分不代表不能投，高分也不代表稳。它真正的作用是**帮你排序和节省时间**，不是替你做决定。

## 设计上几个刻意的取舍

| 取舍 | 原因 |
|---|---|
| **不写爬虫，用 AI 搜索 + 人工确认** | 招聘站有反爬、官网要 JS 渲染、网申链接会失效。维护成本远超收益 |
| **「是否真 AI」单独一列** | 秋招一堆岗位挂 AI 名字实际是传统运营，这一列能滤掉一半噪音 |
| **英语单独占一维** | 只有四级是硬伤，必须提前暴露，不能靠猜 |
| **大厂分档不排除** | 早期版本把所有大厂排除了。但 AI 产品岗的机会恰恰集中在那里，而网申的边际成本只有 15 分钟。改成「不主动搜，遇到就投」 |
| **强制「信息不足就说明白」** | 防止 AI 编造，也防止自己被一个假的高分骗去投不合适的岗 |

## 招聘会 / 面试怎么把它当作品演示

这个仓库本身就是一个可聊的作品——你不用现场跑代码，讲清楚「我为什么做它、它怎么帮我做决策」就行。

**一句话介绍（背下来）：**
> 「秋招我要同时盯几十家公司，干脆自己写了一个岗位筛选 skill：先按我的档案做硬过滤，再六维打分、去重、攒成一张累积表。它现在每天帮我把不值得投的挡在外面，把值得投的说清楚为什么。」

**面试官如果问「那它打的分准吗」——这是加分题，这么答：**
> 「不准，它只是参考。AI 只能读 JD 文字，不知道公司内部的真实筛选规则。所以它的价值不是替我做决定，是帮我排序、省时间。低分不代表不能投，高分也不代表稳。」

**现场可以打开给人看的三样东西：**
1. `README.md` —— 项目说明和一句话介绍
2. `references/01-候选人档案.md` —— 说明「档案不准打分就是假的」，我把自己盘点得很清楚
3. `examples/输出样例.md` —— 一次完整输出长什么样（含「新发现工种」标注）

**记住：别只说「我做了个工具」。要说「我从自己的真实麻烦出发，定义问题、做了最小可用版本、还要按反馈迭代」——这句话才是产品经理思维。**
