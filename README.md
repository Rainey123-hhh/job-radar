# 岗位雷达 · Job Radar

一个给 2027 届秋招生自己用的岗位筛选 AI skill。聚焦**需求分析 / 数据分析 / 数据运营**三个方向。

> **起因：** 秋招要同时盯几十家公司，每天在公众号、牛客、BOSS、公司官网之间来回翻，还得一条条对照自己够不够格。效率低，而且容易漏掉真正合适的。
>
> **核心不是「搜得快」，是「判断得准」**——把不值得投的挡在外面，把值得投的说清楚为什么。

## 这是什么

一个 **skill**，不是一个软件。主体在 [`job-matcher/`](job-matcher/) 目录——一份结构化的说明文件，AI 读完之后就知道怎么帮你筛岗位：先看你是谁、再看这个岗要不要你、最后按固定格式输出。没有一行代码，但它是真的能跑的。

**一句话介绍（背下来）：**
> 秋招我要同时盯几十家公司，干脆自己写了一个岗位筛选 skill：先按我的档案做硬过滤，再六维打分、去重、攒成一张累积表。它现在每天帮我把不值得投的挡在外面，把值得投的说清楚为什么。

## 快速开始

- **当 skill 用**：把 `job-matcher/` 放到本地 skills 目录（Claude Code / Codex / WorkBuddy 都支持），说「用 job-radar 帮我找今天的岗位」
- **复制提示词**：不想装，把 `job-matcher/SKILL.md` + `references/` 下两个文件一起贴给任意 AI，效果一样
- **完整说明**：见 [`job-matcher/README.md`](job-matcher/README.md)

## 设计要点

- **六维打分**：学历门槛、专业、技能、实习相关度、英语、方向契合，满分 30。24+ 优先投，12 以下不投
- **「有无技术含量」单独一列**：很多岗位挂 AI / 数据名字实际是传统运营或纯执行，这一列滤掉噪音；数据运营岗尤其要确认技术门槛是真的
- **匹配度是参考，不是判决**：AI 只能读 JD 文字，不知道公司内部真实筛选规则。它的价值是排序和省时间，不替你做决定
- **只追加不覆盖**：历史数据永远不删

## 项目结构

```
job-matcher/
├── SKILL.md                    skill 本体（给 AI 读的）
├── README.md                   完整项目说明（给人看的）
├── references/
│   ├── 01-候选人档案.md          判断依据：她是谁、会什么、边界在哪
│   └── 02-输出规范与去重规则.md    19 列输出表 + 六维打分 + 去重规则
├── prompts/
│   ├── 01-岗位解析与匹配度打分.md
│   └── 02-简历定制建议.md
├── examples/
│   ├── 输出样例.md
│   └── 真实运行-2026-09-11.md    真实搜索输出（旧方向下的历史快照）
└── data/
    └── 岗位清单模板.md
```

## 路线图
